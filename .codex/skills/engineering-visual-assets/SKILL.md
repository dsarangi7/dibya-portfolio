# Engineering Visual Assets

Use this skill before creating or revising portfolio visuals, diagrams, icons, technical figures, project imagery, SVGs, or brand-like engineering graphics.

Purpose:
Create original visual language for battery systems, AI tools, optics, spectroscopy, diagnostics, data analytics, and engineering R&D.

Asset direction:
- Design original assets only; do not copy proprietary screenshots, internal diagrams, customer materials, or third-party protected visuals.
- Prefer technical clarity over decoration.
- Use visual motifs such as battery cells, marine power systems, signal traces, sensor networks, spectroscopy beams, optical paths, dashboards, models, and diagnostic workflows.
- Match the portfolio style: dark cinematic engineering, holographic overlays, glass panels, fine grid systems, restrained glow, and premium details.
- Keep visuals recruiter-friendly and understandable within seconds.

SVG and diagram standards:
- Use clean, maintainable SVG structure with semantic grouping where useful.
- Keep file sizes reasonable and avoid unnecessary path complexity.
- Use accessible labels or surrounding text when the visual communicates important meaning.
- Do not encode confidential values, real internal architecture, customer names, private file paths, credentials, or proprietary system screenshots.

Workflow:
- Read relevant knowledge files in `docs/references` before choosing subject matter.
- For project visuals, use sanitized concepts and abstracted workflows.
- Check visual assets with the confidentiality skill before publishing or committing.
- Update `TASKS.md` and `CHANGELOG.md` after meaningful asset additions.
